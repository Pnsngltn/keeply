## Application Overview

**Keeply** is a web-based appointment booking system built with Flask that allows service providers to manage their schedules and enables clients to book appointments directly.

### Key Features
- User registration and authentication system
- Service management (providers can define their services)
- Availability management with time slot generation
- Client booking interface with step-by-step selection
- Admin dashboard for appointment management
- Email notifications for new bookings
- Responsive web design with Bootstrap

### Technology Stack
- **Backend**: Python 3.11, Flask 2.3.3
- **Database**: SQLite with CS50 SQL library
- **Frontend**: HTML5, CSS3, JavaScript (ES6+), Bootstrap 5.3
- **Authentication**: Flask-Session with filesystem storage
- **Email**: Flask-Mail with async sending
- **Security**: Flask-WTF CSRF protection
- **Deployment**: Docker with Gunicorn WSGI server

### Application Architecture
The application follows a traditional MVC (Model-View-Controller) pattern:
- **Models**: SQLite database tables defined in schema.sql
- **Views**: Jinja2 HTML templates in templates/ directory
- **Controllers**: Flask routes in app.py handling HTTP requests
- **Utilities**: Helper functions in helper.py

### helper.py - Utility Functions (19 lines)

Contains reusable helper functions for the application.

#### **Login Required Decorator (Lines 4-13)**
def login_required(f):
    @wraps(f)
    def decorated_function(*args, **kwargs):
        if session.get("user_id") is None:
            return redirect("/login")
        return f(*args, **kwargs)
    return decorated_function
**Purpose**: Protects routes by requiring user authentication.

**How It Works**:
- Uses Python decorators to wrap route functions
- Checks if `user_id` exists in session
- Redirects to login page if not authenticated
- Allows normal function execution if authenticated

#### **Time Conflict Detection (Lines 15-16)**
def conflict(s1, e1, s2, e2):
    return not (e1 <= s2 or s1 >= e2)
**Purpose**: Detects if two time ranges overlap.

**Logic Explanation**:
- `s1, e1`: Start and end of first time range (in minutes)
- `s2, e2`: Start and end of second time range
- Returns `True` if ranges overlap, `False` if they don't
- Uses mathematical logic: ranges don't conflict if one ends before the other starts

### schema.sql - Database Structure (60 lines)

Defines the complete SQLite database schema for Keeply.

#### **Table Drop Statements (Lines 1-6)**
DROP TABLE IF EXISTS appointments;

#### **Users Table (Lines 8-15)**
CREATE TABLE users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    username TEXT NOT NULL UNIQUE,
    pwd_hash TEXT NOT NULL,
    email TEXT NOT NULL UNIQUE,
    phone TEXT NOT NULL
);
**Purpose**: Stores service provider accounts.

**Field Details**:
- `id`: Auto-incrementing primary key
- `username`: Unique identifier for login and booking URLs
- `pwd_hash`: Hashed password (never store plain text)
- `email`: Contact email for notifications
- `phone`: Contact phone number

#### **Clients Table (Lines 17-23)**
CREATE TABLE clients (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    name TEXT NOT NULL,
    email TEXT NOT NULL,
    phone TEXT NOT NULL
);
**Purpose**: Stores client information for appointments.

**Design Note**: No unique constraints on email/phone to allow multiple clients with same contact info (e.g., family members).

#### **Services Table (Lines 25-33)**
CREATE TABLE services (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL,	
    name TEXT NOT NULL,
    description TEXT NOT NULL,
    price INTEGER NOT NULL,
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);
**Purpose**: Defines services offered by each provider.

**Relationships**:
- `user_id`: Links to users table (many services per user)
- `ON DELETE CASCADE`: Automatically deletes services when user is deleted

#### **Time Slots Table (Lines 35-45)**
CREATE TABLE timeslots (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL,
    date TEXT NOT NULL,
    time_start TEXT NOT NULL,
    time_end TEXT NOT NULL,
    duration INTEGER NOT NULL, -- in minutes
    status TEXT  DEFAULT 'Free', -- Free or Booked
    FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);
**Purpose**: Manages available time slots for booking.

**Design Decisions**:
- `date TEXT`: Stores dates as strings (YYYY-MM-DD format)
- `time_start/time_end TEXT`: Stores times as strings (HH:MM format)
- `status`: Enum-like field with 'Free' or 'Booked' values
- `duration`: Slot duration in minutes for validation

#### **Appointments Table (Lines 47-59)**
CREATE TABLE appointments (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL,
    client_id INTEGER NOT NULL,
    slot_id INTEGER NOT NULL,
    service_id INTEGER NOT NULL,
    status TEXT DEFAULT 'Pending', -- Pending, Confirmed and Finished
    FOREIGN KEY (user_id) REFERENCES users(id),
    FOREIGN KEY (client_id) REFERENCES clients(id),
    FOREIGN KEY (slot_id) REFERENCES timeslots(id),
    FOREIGN KEY (service_id) REFERENCES services(id)
);
**Purpose**: Central table linking all appointment data.

**Status Workflow**:
- `Pending`: Initial state after booking
- `Confirmed`: Provider accepts appointment
- `Finished`: Appointment completed
- `cancelled`: Appointment cancelled (handled in code, not schema)

**Relationship Complexity**:
This table demonstrates many-to-many relationships through foreign keys, connecting users, clients, time slots, and services in a single appointment record.

### Troubleshooting Common Issues

**Database Connection Issues**:
- Check SQLite file permissions
- Verify database file exists
- Check CS50 SQL library installation

**Email Sending Problems**:
- Verify SMTP credentials
- Check email provider settings
- Confirm firewall rules
- Test with different email providers

**Session Management Issues**:
- Clear browser cookies
- Check session storage permissions
- Verify SECRET_KEY configuration
- Restart application server

**Docker Deployment Issues**:
- Check container logs: `docker-compose logs app`
- Verify volume mounts
- Check network configuration
- Validate environment variables
